# Troubleshooting

[README](../README.md) · [Usage](usage.md) · [Other clients](clients.md) · [Tuning](tuning.md) · [How it works](how-it-works.md) · **Troubleshooting** · [Changes](changes.md) · [Development](development.md)

- **Start here**: `dsh-romeo --doctor` checks each piece in turn and says what to type for the one that fails.
- **A model job ended before answering**: dsh-romeo says why and what to type. `a GPU had only 73.82/95.0 GiB free at start` means an earlier job left its file cache on that node's GPU memory: `dsh-romeo --setup` installs the clean-up that frees it at each start, then `dsh-romeo --launch` again. `romeollmtool's gateway stopped (24 h lifetime)` cancels every job: any dsh-romeo command starts it again for 24 h.
- **`cannot connect to 'romeo' over SSH`**: `ssh romeo hostname` must work without a password (see [Usage](usage.md#install)).
- **The job waits in the queue**: `dsh-romeo --status` and the waiting line say why, in words: no free GPU nodes yet, other jobs go first, or the project's GPU limit is reached (60 GPUs per project, shared with its other members: a Kimi job takes 32). Waiting can stop with Ctrl-C: the job stays in the queue and `dsh-romeo` picks it up later. A job that would never start stops the wait at once with what to do: the project's GPU hours used up, a `DSH_ROMEO_TIME` over the allowed time, or a job held by Slurm.
- **`your ROMEO login cannot read the weights of Kimi-K3.1-Pro`**: Kimi's weights are in project r260105's storage, open to its members only; dsh-romeo checks before it submits a job, which would otherwise fail after its wait. Use `--models deepseek` (its weights are in the shared storage), or ask to be added to the project.
- **`Slurm refuses project ...`**: the project code in `~/.config/dsh-romeo/config` is not one of yours, or it ended: `install.sh --project rXXXXXX` (`sacctmgr show assoc user=$USER` on ROMEO lists yours).
- **`the model has been loading for longer than usual`**: more than 25 min (Kimi: 35) since the job started. The wait goes on; `dsh-romeo --logs` shows where it is (a slow file system, or a hang: then `dsh-romeo --stop` and `--launch`).
- **`model job ends in N min`**: the agent's job has less than 30 min left (`DSH_ROMEO_TIME`, 8 h by default). `dsh-romeo --launch` submits a new one while you work; the gateway sends new requests to it once it answers.
- **The job ends while loading**: read its log with `dsh-romeo --logs` (or `ssh romeo /apps/romeotools/romeollmtool/romeollmtool logs`). A node whose GPU memory is partly taken makes vLLM fail at start: `dsh-romeo --launch` again.
- **`cannot forward 127.0.0.1:11318`**: the message names the program that holds the port (stop it, or set `DSH_ROMEO_PORT`), or gives ssh's own reason when the port is free; dsh-romeo first retries on a new SSH connection. The `ssh -N -L ...` it suggests shows ssh's own message for that forward (not `--stop`, which would also cancel the model jobs).
- **`the gateway refuses the key`**: the key dsh-romeo read is not the gateway's (HTTP 401); dsh-romeo stops at once instead of waiting. `dsh-romeo --doctor` tests the key against the gateway.
- **The model is ready but dsh answers `Clé API invalide ou absente`**: dsh used another key than the gateway's. A `ROMEO_LLM_KEY` saved in dsh's credential store (`~/.dsh/.credentials.yaml`, from its Settings) wins over the one dsh-romeo passes; dsh-romeo now removes it at each start, and `dsh-romeo --doctor` reports it. A dsh or desktop app started by hand (not through dsh-romeo) has no key at all.
- **The desktop app**: `dsh-romeo --desktop` restarts it only when the key or dsh-romeo's settings changed; otherwise it reopens the tunnel and leaves the app as it is. `macOS did not open DeepSeek Harness` gives macOS's own reason (a damaged copy: reinstall it). `not running 30 s after opening`: a macOS dialog (first opening, permissions) may wait for you. The app opened from the Dock gets the key too, until `dsh-romeo --stop`, but needs the tunnel: run `dsh-romeo --desktop` first.
- **A client shows connection errors after your computer slept**: run `dsh-romeo` (or `--serve`) again; the tunnel is reopened and dsh keeps your sessions.
- **`web search unavailable: RustXNG on ROMEO: ...`** (`--web on`): dsh starts without web search. `download failed`: the login node could not reach GitHub (try again later); `checksum mismatch`: the file downloaded is not RustXNG 0.28.0, so it is not installed. In dsh, `the SSH connection to ROMEO is closed`: run `dsh-romeo` again after a sleep.
- **`fast gateway unavailable`**: the patch no longer fits `romeollmtool` (after an update, for example); dsh-romeo uses the standard gateway meanwhile. The reason is the last line of the message; the logs are in `~/.dsh-romeo/gateway` on ROMEO.
- **`fiche ... not found on ROMEO`**: `dsh-romeo --setup` (`--launch` installs the fiches it needs by itself).
- **opencode: `Database is not empty and has no session table`**: a database left by another opencode version in `~/.local/share/opencode`; nothing to do with dsh-romeo.
