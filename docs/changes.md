## 2026-11-07

- `kimi+deepseek`: subagents really go to DeepSeek in the Web UI and the desktop app. dsh's model selection, off by default, let a subagent take only the agent's own model there, so they ran on Kimi. It is now on with both models allowed: DeepSeek by default, and the agent may pick Kimi for a subagent. Open a new session after updating.
- `--web on|off` (remembered): web search in dsh through RustXNG on the ROMEO login node, nothing to install on your computer. Its static binary (0.28.0) is downloaded once and checked against its pinned SHA-256; each search runs `rustxng mcp` over dsh-romeo's SSH connection, so no port is opened on the shared login node. About 1 s and 10 results per search. Works in the Web UI, `headless` and `--desktop`.
- Tuning finished: the last A/B runs on ROMEO (NCCL queue pairs, async scheduling and a 16K prefill budget for DeepSeek; NCCL queue pairs and DCP2 for Kimi) did not beat the production fiches, which stay as they are ([Tuning](tuning.md)). Images and voice checked again on both production fiches. README: the speeds measured.

## 2026-11-06

- More errors caught before they cost a wait, each with what to type: Kimi's weights not readable by your login (checked before the job is submitted), a project Slurm refuses, a full ROMEO home, a `DSH_ROMEO_TIME` that is not `HH:MM:SS` up to 24 h, and a queued job that would never start (GPU hours used up, time over the allowed one, held). The queue reasons are said in words (the project's GPU limit reached, no free nodes, maintenance). A model that loads much longer than usual is reported once, and a job with less than 30 min left is said when dsh opens.
- `--desktop`: an app that already runs with the same key and settings is not restarted (after a sleep, only the tunnel is reopened); macOS refusing to open the app, an app that does not start within 30 s, and an app profile that cannot be written are said with what to do. The key is also given to launchd until `--stop`, so the app works when opened later from the Dock.
- `--doctor` checks that your login can read each model's weights: Kimi's are open to project r260105's members only.
- `--launch` installs the fiches it launches and the job clean-up when this version's differ from those on ROMEO: an update no longer needs `--setup` first.
- Shorter `--help` and README: the four everyday commands first, then the options, the other clients, and what to run when something is wrong.
- Kimi: DCP4 with all-to-all exchanges instead of DCP8, so each request's KV exchanges stay inside a node: 38 tok/s for one agent (35), 23.5 at 4 agents (15.9), 29 at 9 (12-18), 14 at 9 agents on 128K prompts (9.5), in two runs plus a staggered grid, functional tests unchanged. The KV cache goes from 21.1M to 11M tokens, still 10 full 1M contexts. Run `dsh-romeo --setup`, then relaunch the Kimi job.
- A model job that ends before answering is explained: dsh-romeo reads Slurm's record and the end of the job's log and says why (a GPU with too little free memory at start, out of GPU memory, no room for the KV cache, time limit, host memory, node failure, cancelled, or romeollmtool's gateway stopping at the end of its 24 h, which cancels every job), with what to type next. `--status` shows a failed last job in red with its reason.
- Before a job starts, each node drops the page cache that earlier jobs left on the GPU memory (GH200 exposes HBM as NUMA memory: a node had only 72-74 GiB free out of 95, so Kimi refused to start) and our stale NCCL files in `/dev/shm` (12 GB found on one node): `share/prestart/sitecustomize.py`, installed by `--setup`, on the fiches' `PYTHONPATH`. Run `dsh-romeo --setup`.
- Kimi: the engine now carries vLLM PR #53948 (ported onto the K3.1 engine, `engines/vllm-k31-pp`), and the fiche turns async scheduling on: +14 % for one agent, +35 to +38 % per agent at 16 agents (13.6-13.9 against 10.1 tok/s), +48 % for 9 agents on 128K prompts, in two runs, functional tests unchanged. Run `dsh-romeo --setup`, then relaunch the Kimi job.
- DeepSeek: `--gpu-memory-utilization 0.88` instead of 0.82, so 9.1M tokens of KV cache instead of 6.2M at the same speed (A/B on ROMEO); FlashInfer compiles into the node's `/tmp` (a cache shared with Kimi's engine crashed a start). Run `dsh-romeo --setup`, then relaunch the DeepSeek job.
- `install.sh --search-engine rustxng`: RustXNG (a Rust rewrite of SearXNG, same JSON API, about a fifth of the memory) on `127.0.0.1:8888` instead of SearXNG, pinned to 0.28.0 by digest. Evaluated on ROMEO against SearXNG: as relevant on 20 coding queries; offered as an option, SearXNG stays the default.
- DeepSeek: DSpark now draws its draft tokens from the draft's distribution (`draft_sample_method: probabilistic`) instead of greedily: +12 to +19 % per agent at 64 agents and +15 to +19 % at 16 over the 0.33 fiche, in two runs, output distribution unchanged (exact rejection), 4 % less KV cache. Run `dsh-romeo --setup`, then relaunch the DeepSeek job.
- Kimi-K3.1-Pro reads images: its fiche serves the vision encoder (MoonViT-V2), and with `kimi` or `kimi+deepseek` it is Kimi that reads the screenshots pasted in dsh. Tested on ROMEO: the image read correctly, same KV cache (21.1M tokens) and same speed as text only. Run `dsh-romeo --setup`, then relaunch the Kimi job.
- DeepSeek-V4.1-Flash-1017 moves to vLLM 0.33.0: +19 % per agent alone, +34 % at 64 agents, +49 % in all, half the time to first token under load, a bit more KV cache (A/B on ROMEO against 0.31, same settings, same functional tests). Its kernels compile into each node's `/tmp` (the fiche's `__USER__` becomes your login at install). Run `dsh-romeo --setup` (or `./install.sh`), then relaunch the DeepSeek job; the first start compiles for a few more minutes.
- Errors: a key the gateway refuses (401) stops the wait at once instead of looping; what this computer lacks (dsh, the app, the `--run` client, an unknown option) is said before any job is submitted; the key is read before launching; a failure after a submit says the job keeps running; squeue or SSH not answering is "unknown", never "no job" (`--stop` exits 1 then); a dead SSH connection after sleep is replaced; a job ending while loading points to `--logs`, which falls back to romeollmtool's last log.
- State: `--voice off` removes the Whisper forward and key and says when its job still runs; one voice watcher at a time; an invalid remembered `--models` is forgotten instead of blocking every command; `--stop` closes connections opened with an earlier `ROMEO_SSH_HOST`; `--desktop` writes the app's profile in `~/.dsh` even with `DSH_HOME` set, and skips the subagent presets when the app's dsh cannot be found; config values with spaces or quotes reach ROMEO intact; `--env`/`--serve` stdout stays clean with a chatty ROMEO login; two starts at once no longer race on the connection or temporary files; `~/.ssh` is created private.
- Fixes: `--doctor` closes the connection it opened and tests the key against the gateway; a dsh credential file left with no other key stays writable by dsh; silent exits under `set -e` (free port with a refused forward, the app's dsh not found, an unreadable dsh version) now give their message.

## 2026-11-05

- The ready line gives the gateway's URL on ROMEO and the local tunnel URL, each on its own line.
- Fix: a `ROMEO_LLM_KEY` saved in dsh's credential store won over the gateway's key passed by dsh-romeo, so dsh got `Clé API invalide ou absente` once the model was up; dsh-romeo removes that entry before starting dsh or the app, and `--doctor` reports it. A refused SSH forward is retried on a new connection, then reported with ssh's own reason or the program holding the port, instead of always blaming "another program".
- Terminal: `--status` is a table (model, job, state, nodes, time left or the queue's estimated start), the tunnel counts as open only when it leads to the gateway, errors end with the command to type next, `--launch` with `--status`/`--stop`/`--setup` is refused instead of ignored, Ctrl-C while waiting says the job keeps running, the waiting line no longer repeats every poll in a log, `NO_COLOR` and `TERM=dumb` turn colors off, and a bell plus a desktop notification say when a model is ready after a long wait. New `--doctor` (checks this computer, SSH, ROMEO, the fiches and the key), `--completion bash|zsh`, `--logs [-f]`; `--version` also gives dsh's, the app's and Node.js's versions. `--help` is grouped by use.
- `--stop` cancels every dsh-romeo job, also those of an earlier `--models`, and goes on past a job it cannot cancel; Kimi takes one job at most (a second `--launch` says one is queued); curl reads the gateway key from stdin; the fast gateway refuses a port held by another user; `install.sh` checks its options' values, keeps settings it does not write, and needs Node.js 20.3. `DSH_ROMEO_EFFORT=none` is now `off` (dsh refused `none`). `--desktop` quits the app before writing its patch, and stops if it does not quit.
- With `kimi+deepseek`, DeepSeek also writes the session titles and dsh-prompt-predict's suggestions (when it is on, without reasoning); before, they ran on Kimi or on the plugin's own setting. The MCP client needs servers of your own: documented.
- Voice input with a Whisper job that starts after dsh: a background watcher opens the tunnel once the job runs, and the plugin reads the job's key from a file at each recording, so the microphone works without restarting dsh.
- `install.sh` keeps the optional plugins working on a newer dsh: an installed version outside its declared dsh range moves to the latest version (keeping its on/off state), and a refused pinned version falls back to the latest.
- Test suite: passes in full on a ROMEO login node too (the skill's env.sh can be told it runs remote, and the fast gateway test no longer finds ROMEO's real romeollmtool Python).
- `install.sh` installs optional third-party dsh plugins, turned off, in the `web` and desktop app profiles: dsh-prompt-predict (next-prompt suggestions) and dsh-sidenote (side chat). Turn them on in dsh's Plugins page; `--no-plugins` skips them. Checked on dsh 0.2.2-rc.1: they load and show under *Installed plugins* with their switch off. Plugins that import dsh internals (dsh-answer-reviewer, dsh-task-supervisor, dsh-claude-move) do not load on 0.2.2 and are left out.
- The README GIF plays in 16 s instead of 33: `tests/demo.py render` cuts pauses to 45 % (typing kept as recorded).
- Images with DeepSeek-V4.1-Flash-1017: its fiche now serves the vision encoder (tested on ROMEO: image read correctly, 6.34M tokens of KV cache instead of 6.5M, 160 tok/s for one agent), and dsh-romeo declares a model `input: [ text, image ]` unless its fiche passes `--language-model-only`, so you can paste screenshots in dsh. Kimi-K3.1-Pro stays text only until its own test runs. Run `dsh-romeo --setup` (or `./install.sh`) to copy the new fiche, then relaunch the DeepSeek job.
- Voice input: `dsh-romeo --voice on --launch` runs Whisper large-v3-turbo on 1 GPU (new fiche `dsh-whisper-large-v3-turbo`) and turns on dsh's microphone button with Whisper as its recognizer ([share/speech-whisper-romeo.mjs](../share/speech-whisper-romeo.mjs)); dsh's own local recognizer, SenseVoice, does not know French. Remembered like `--models`. Tested on ROMEO: Whisper starts in under 4 minutes on 1 GPU and transcribes 8 s of French in 0.2 s; recordings go straight to the job through a second SSH forward, since romeollmtool's gateway cannot relay audio uploads (python-multipart missing).
- `--models`, `--launch` and `--serve`/`--env`/`--desktop` go in any order: `dsh-romeo --models kimi+deepseek --desktop --launch` launched nothing before (`--launch` was only read before the command).

## 2026-11-04

- Checked with dsh 0.2.2-rc.1 (npm `next`, and the desktop app 0.2.2-rc.1). `install.sh` installs that version when Node.js is 24.9 or later. `--desktop` reads the presets it restates with the app's own dsh, whose version can differ from the npm one (0.2.1 kept a `list_agents` tool that 0.2.2-alpha.3 lacks).

- `--models` is remembered for the next runs, so `dsh-romeo --desktop` after `dsh-romeo --models kimi+deepseek --launch` opens the app on Kimi. `--desktop` keeps the settings the app saves in its `cordis.patch.yml` (it overwrote them at every start) and replaces only dsh-romeo's own rows.

- Choice of models: `dsh-romeo --models deepseek|kimi|kimi+deepseek` (or `DSH_ROMEO_MODELS` in the config). `kimi+deepseek` runs Kimi-K3.1-Pro as the agent and DeepSeek-V4.1-Flash-1017 for its subagents: both jobs launched and waited for, both models in dsh's list, dsh's `subagent` tool routed to DeepSeek in every preset. `install.sh` writes `DSH_ROMEO_MODELS`; a `DSH_ROMEO_FICHE` left at the old default is dropped, a fiche of your own is kept.

- Kimi-K3.1-Pro, with `DSH_ROMEO_FICHE=dsh-kimi-k3.1-pro-1m`: 8 nodes, TP8 x PP4 x DCP8, 1M context, tuned by an A/B on ROMEO ([Tuning](tuning.md#kimi-k31-pro)). Tested on a real job: answers at the four reasoning efforts, parallel tool calls, 763K-token prompts. dsh, opencode and `--serve` show the model's own name.
